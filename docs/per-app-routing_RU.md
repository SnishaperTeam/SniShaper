# Маршрутизация по приложениям

Поле «Маршрутизация по приложениям» в группе сайтов ограничивает правило соединениями перечисленных процессов (например, `telegram.exe, discord.exe`). Этот документ описывает поддержку платформ, способ определения приложений и взаимодействие правил по приложениям с доменными правилами и маршрутизацией по умолчанию.

## Поддержка платформ и ограничения

| Платформа | Поддержка | Определение |
|-----------|-----------|-------------|
| Windows | ✅ | Таблица TCP-соединений (`GetExtendedTcpTable`) → PID → имя процесса, с кэшем |
| Linux | ✅ | inode из `/proc/net/tcp*` → `/proc/<pid>/comm` |
| macOS | ✅ | Поиск соединения через `lsof` → PID → имя процесса (первый вызов имеет холодный старт, далее кэш) |
| Другие платформы | ❌ | Процесс всегда неизвестен; правила по процессам никогда не срабатывают (fail closed) |

- Обратный поиск процесса выполняется, только если **существуют включённые правила по процессам**; при их отсутствии накладных расходов нет.
- Сопоставляется только **базовое имя исполняемого файла** (без пути), через запятую, без учёта регистра.
- Если процесс неизвестен (сбой поиска, системные ограничения, неподдерживаемая платформа), правило по процессам не применяется — остальной трафик никогда не затрагивается ошибочно.
- Загрузка конфигурации с правилами по процессам на неподдерживаемой платформе выдаёт предупреждение в отчёте о миграции.

## Взаимодействие с доменными правилами / маршрутизацией по умолчанию

1. **Правила по процессам приоритетнее любых доменных**: если цель подходит и под правило по процессам, и под доменное, побеждает правило по процессам (бонус процесса выше всех доменных баллов).
2. **Правила «процесс + домен» требуют совпадения обоих условий**: доменное поле сужает правило по процессам; несовпадение домена исключает правило (оно не превращается в правило только по процессу).
3. **Пустой список доменов = все адресаты для процесса**: правило по процессам с пустым (или `*`) списком доменов покрывает все соединения этого процесса.
4. **Нет совпадений → маршрутизация по умолчанию**: если ни одно правило не подошло, решение принимают глобальный режим и авто-маршрутизация.
5. Инструмент проверки правил (кнопка «Тест» на странице правил) принимает имя процесса и моделирует срабатывание правил по процессам через тот же конвейер, что и реальные соединения.

Регрессионные случаи конфликтов — в `app/app_perapp_test.go` (процесс против домена, процесс+домен, неизвестный процесс, маршрутизация по умолчанию).
