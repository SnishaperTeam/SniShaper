# 配置文件（Configuration Profiles）

配置文件是为不同网络或使用场景保存的**命名配置快照**（一份 `settings.json` + 一份 `rules/config.json`）。本文档面向需要了解存储布局与导出格式的用户与开发者；日常使用见 Wiki「界面配置指南」。

## 存储布局

```
<用户配置目录>/            # Windows: %APPDATA%\snishaper，Linux/XDG: ~/.config/snishaper
└── profiles/
    ├── _active.json       # 当前激活的配置文件标记 {"name": "...", "switched_at": "..."}
    ├── work/
    │   ├── settings.json  # 该配置文件的设置快照
    │   └── rules.json     # 该配置文件的规则快照
    └── home/
        ├── ...
```

- **实时配置文件永远是运行时唯一数据源**：`config/settings.json` 与 `rules/config.json` 不会被移动，配置文件只在切换时与之互相拷贝。不使用配置文件的安装完全不受影响（既有配置天然保留）。
- 每个配置文件目录独立保存完整的规则（含站点组 DNS 模式）、上游、端口等设置，彼此天然隔离。
- 名称规则：字母、数字、中文、空格、`_`、`-`，最长 64 字符；`_` 前缀保留。

## 切换语义（连接活动时的安全行为）

1. 若代理正在运行：先停止代理（TUN / 系统代理 / 活动连接随之一并关闭）。
2. 将当前实时配置快照回写到**离开的**配置文件目录（防止切换丢失未保存的修改）。
3. 目标配置文件的两个快照覆盖实时配置文件。
4. 应用内 RuleManager 与核心子进程各自重载配置；监听端口随目标配置文件生效。
5. **不会自动重启代理**：切换完成后由用户手动启动（界面在确认对话框中明示）。

## 导出 / 导入格式

导出产物是单个 JSON 文件（写入日志目录 `profile-exports/`）：

```json
{
  "format": "snishaper-profile",
  "version": 1,
  "name": "work",
  "exported_at": "2026-10-30T12:00:00Z",
  "settings": { ... },
  "rules": { ... }
}
```

导入在落盘前把 `settings` / `rules` 写入临时目录并用**与实时匹配相同的 RuleManager 加载管线**校验：未来版本号、无法解析的 JSON、非对象结构会被拒绝并返回引擎自己的错误说明；迁移警告原样透传给界面展示。校验失败时不会写入任何配置文件。
