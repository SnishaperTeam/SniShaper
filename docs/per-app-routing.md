# 按应用程序分流（Per-Application Routing）

站点组的「按应用程序分流」字段把一条规则限定为仅对指定进程发起的连接生效（如 `telegram.exe, discord.exe`）。本文说明各平台的支持情况、应用身份的识别方式，以及应用规则与域名规则、默认路由的交互。

## 平台支持与限制

| 平台 | 支持 | 识别方式 |
|------|------|----------|
| Windows | ✅ | TCP 连接表（`GetExtendedTcpTable`）反查 PID → 进程名，带缓存 |
| Linux | ✅ | `/proc/net/tcp*` inode → `/proc/<pid>/comm` |
| macOS | ✅ | `lsof` 反查连接 PID → 进程名（首次调用有冷启动开销，后续命中缓存） |
| 其他平台 | ❌ | 进程恒为未知，进程规则一律不参与匹配（fail closed） |

- 只有当**存在启用中的进程规则**时才会执行进程反查；没有任何进程规则时零开销。
- 仅匹配**进程可执行文件基名**（不含路径），逗号分隔、不区分大小写。
- 进程未知（反查失败、系统限制或不支持的平台）时，进程规则永不生效——不会误伤其他流量。
- 在不支持的平台上加载含进程规则的配置时，配置迁移检查会给出平台警告（见迁移报告）。

## 与域名规则 / 默认路由的交互

1. **进程规则优先于一切域名规则**：同一目标同时命中进程规则与域名规则时，进程规则获胜（进程加成高于所有域名得分等级）。
2. **进程 + 域名规则需同时匹配**：域名字段进一步收窄进程规则的适用范围；域名不匹配时该规则不参与（而不是回退成纯进程规则）。
3. **域名为空 = 该进程的全部目标**：进程规则的域名清单留空（或 `*`）表示该进程的所有连接。
4. **都不命中走默认路由**：无任何规则匹配时，走全局模式与自动路由（auto-routing）的默认决策。
5. 规则匹配测试（规则页「测试」）可填入进程名模拟进程规则的命中结果，其说明与真实连接使用完全相同的匹配管线。

冲突回归用例见 `app/app_perapp_test.go`（进程 vs 域名、进程+域名、进程未知、默认路由）。
