# Пакеты Linux (deb / RPM / AppImage)

Помимо существующего распространения в виде архива, SniShaper предоставляет пакеты для дистрибутивов Linux. Определения упаковки — в `packaging/`; CI-конвейер — `.github/workflows/linux-packages.yml` (запускается вручную, не блокирует слияния).

## Оценка форматов

| Формат | Вердикт | Обоснование |
| --- | --- | --- |
| `.deb` | ✅ предоставляется | Наибольшее покрытие в Debian/Ubuntu и производных; одна конфигурация nfpm, минимальная стоимость поддержки |
| `.rpm` | ✅ предоставляется | Экосистема Fedora/RHEL/openSUSE; использует ту же конфигурацию nfpm, что и deb — почти бесплатно |
| AppImage | ✅ предоставляется | Без установки, один файл, подходит для дистрибутивов вне покрытия менеджеров пакетов; только GUI (CLI — через deb/rpm или архив) |
| Flatpak / Snap | ❌ не предоставляется | Песочница конфликтует с TUN/системным прокси (нужны привилегированные интерфейсы и сетевой стек хоста); стоимость поддержки слишком высока |

## Поддерживаемые дистрибутивы

GUI построен на Wails v3 (GTK4 + WebKitGTK 6.0); зависимости времени выполнения:

| Дистрибутив | Минимум | Библиотеки |
| --- | --- | --- |
| Ubuntu | 24.04 LTS | `libgtk-4-1`, `libwebkitgtk-6.0-4` |
| Debian | 13 (trixie) | `libgtk-4-1`, `libwebkitgtk-6.0-4` |
| Fedora | 40+ | `gtk4`, `webkitgtk6.0` |

- deb жёстко зависит от `libgtk-4-1`; WebKit указан как recommends, поскольку имя пакета различается между релизами (без него GUI падает при запуске с понятной ошибкой; CLI не страдает).
- Зависимости RPM используют имена Fedora; пользователям openSUSE следует взять архивную сборку или самостоятельно установить аналогичные библиотеки.
- AppImage содержит все зависимости — GTK/WebKit не нужны, но **режиму TUN по-прежнему нужны root** и `/dev/net/tun`.
- Архитектуры: `amd64` и `arm64`.
- Любому формату нужны **права администратора** для системного прокси и TUN; обычный прокси-режим (браузер вручную на 127.0.0.1:8080) работает без повышения прав.

## Состав пакета (deb / rpm)

| Файл | Описание |
| --- | --- |
| `/usr/bin/SniShaper` | GUI-приложение |
| `/usr/bin/snishaper` | Headless-CLI |
| `/usr/share/applications/snishaper.desktop` | Ярлык рабочего стола (с локализованными комментариями zh_CN / ru) |
| `/usr/share/icons/hicolor/512x512/apps/snishaper.png` | Значок приложения |

## Поведение при обновлении и удалении

- **Обновление**: `apt install ./snishaper_<версия>_amd64.deb` (или `dnf upgrade ./snishaper-<версия>.rpm`) заменяет файлы пакета в `/usr` на месте; удалять старую версию не нужно.
- **Удаление**: `apt remove snishaper` / `dnf remove snishaper` удаляет только файлы пакета.
- **Пользовательские данные недоступны менеджеру пакетов**: конфигурация, логи, правила и сертификаты находятся в `~/.config/snishaper` и не затрагиваются при обновлении и удалении; каталог можно удалить вручную, когда данные больше не нужны.
- AppImage — один файл: удаление файла удаляет приложение; `~/.config/snishaper` также не затрагивается.

## Локальная сборка

```bash
# Предварительные требования: go, node, dev-пакеты GTK4/WebKitGTK (см. docs/build_RU.md)
./build.sh --platform linux --arch x64 --type cli --type gui
go install github.com/goreleaser/nfpm/v2/cmd/nfpm@latest
./packaging/fetch-linuxdeploy.sh amd64
./packaging/build-packages.sh amd64 <версия>
# Результат: .deb / .rpm / .AppImage в build/dist/linux/amd64/
```

CI: запустите рабочий процесс `linux-packages` вручную на вкладке Actions; он собирает артефакты по архитектурам и автоматически проверяет содержимое deb (бинарники, desktop-файл, значок).
